# POS صيانة (MVP قابل للتوسع)

هذا المستودع يحتوي **Scaffold** أولي لنظام إدارة صيانة أجهزة POS متعدد المستأجرين (Multi-tenant) مع RTL عربي.

## قرار الـ Stack
- **Next.js 14 + TypeScript**: بناء سريع، App Router، مناسب لتطبيق ويب Responsive.
- **PostgreSQL 15**: علاقات قوية + فهارس + JSONB + دعم ممتاز لـ RLS.
- **RBAC + Feature Flags** على مستوى `tenant`.
- **RLS** لعزل بيانات كل محل.

## تحليل المتطلبات (مختصر)
- نظام فواتير صيانة + حالات تشغيل واضحة.
- تتبع تدقيق كامل (Audit Timeline) لكل تعديل.
- دعم مراجعات مرتبطة بالفاتورة الأصلية.
- طباعة فاتورة وستيكر بإعدادات مقاس مخصصة لكل محل.
- إدارة مخزون وقطع غيار (MVP بدون خصم تلقائي).
- حقول مخصصة لكل محل لتعريف نموذج الإدخال.
- تقارير أساسية للمدير.

## User Stories
1. كـ **كاشير** أريد إنشاء أمر صيانة بسرعة مع حفظ العميل والجهاز والحالة الأولى.
2. كـ **فني** أريد تغيير الحالة وإضافة ملاحظات فنية لرؤية تقدم العمل.
3. كـ **مدير** أريد التحكم بالصلاحيات لكل دور داخل المحل.
4. كـ **مدير** أريد عزل البيانات بحيث لا يرى أي مستخدم بيانات محل آخر.
5. كـ **مدير** أريد سجل تدقيق كامل قبل/بعد لكل تعديل على الفاتورة.
6. كـ **كاشير** أريد تسجيل دفعة جزئية وحساب المتبقي تلقائياً.
7. كـ **موظف** أريد إنشاء مراجعة مرتبطة بنفس رقم الفاتورة (1432-1).
8. كـ **مدير** أريد التحكم بمقاس الستيكر من الإعدادات.
9. كـ **مدير** أريد إضافة حقول مخصصة للنموذج مع التحقق.
10. كـ **مدير** أريد تقارير الحالات والمبالغ والمتأخرات.

## تصميم قاعدة البيانات
- ERD نصي + DDL كامل في: `docs/database.sql`.
- يشمل:
  - جداول الـ tenants/users/RBAC/plan features.
  - work_orders + followups + custom fields + inventory.
  - audit_logs بنمط قبل/بعد (`old_values/new_values`).
  - فهارس رئيسية وقيود uniqueness/check.
  - سياسات RLS لعزل المستأجر.

## API Endpoints (MVP)
> التفاصيل في `docs/api.md`.

- `POST /api/work-orders` إنشاء أمر صيانة + audit + catalog auto-upsert.
- `GET /api/work-orders` قائمة مع فلاتر الحالة/التاريخ.
- `GET /api/work-orders/:id` تفاصيل + timeline.
- `PATCH /api/work-orders/:id` تعديل عام + سجل تدقيق.
- `POST /api/work-orders/:id/status` تحديث الحالة.
- `POST /api/work-orders/:id/payments` تحديث الدفع (partial/full).
- `POST /api/follow-ups` إنشاء مراجعة مرتبطة.
- `GET /api/inventory` و `POST /api/inventory` إدارة المخزون.
- `GET /api/reports` تقارير تجميعية للمدير.

## خطة التنفيذ على 3 مراحل
1. **المرحلة 1 (MVP)**: فواتير + حالات + طباعة + audit + بحث.
2. **المرحلة 2**: مراجعات + مخزون + تحسينات UX.
3. **المرحلة 3**: باقات + صلاحيات متقدمة + تقارير متقدمة.
